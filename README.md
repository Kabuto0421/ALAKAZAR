# ALAKAZAR — 6×6 Tactics

既存の「Ruins Delver Prototype」の素材・描画デザイン・将棋移動コードを引き継いだ、Godot 4.7用の戦闘プロトタイプです。タイトルはALAKAZARです。

## 起動

- このフォルダの `project.godot` をGodot 4.7でインポートし、F6またはF5で実行します。
- コマンドラインから実行：

```sh
godot --path .
```

## 操作

| 入力 | 操作 |
| --- | --- |
| 1 / 2 / 3 | 金（ハンマー）・銀（剣）・桂（斧）の無料プレビュー |
| Q / E / Tab | プレビューする武器を順に選択 |
| 装備する 1 AP | 選択した武器へ持ち替え |
| 向き変更 / プレイヤーをクリック | 向きと移動・攻撃範囲を無料で確認 |
| この向きにする 1 AP | 選んだ向きへ変更 |
| 光るマスをクリック | 移動、または敵がいる場合に攻撃 |
| Space | ターン終了 |
| R | 現在の戦闘をやり直す |
| H | ルールの開閉 |
| 4 / 5 / 6 | 消耗品ショートカットを選択 |
| B | バッグの開閉 |
| 右クリック / Esc | アイテム選択・配置・向き指定をキャンセル |
| ↑ / → / ↓ / ← | 向き変更中は方向をプレビュー。魔弾精霊の配置後は発射方向を確定 |

敵にカーソルを重ねると、右下に3×3の移動ビューが表示されます。中央が敵、緑が移動可能な隣接マス、赤が探索者への攻撃マスです。赤い攻撃マスの敵は1クリックで攻撃し、攻撃範囲外の敵をクリックすると詳細表示を固定できます。空きマスをクリックすると固定表示を解除します。

## 戦闘ルール

6×6の盤面。敵が上、探索者が下から開始し、敵→自分の順に行動します。敵を全滅させると勝利、探索者のHPが0になると敗北。3種類の敵編成を順に遊べます。

探索者は赤いハート5個・AP2。移動1 AP、攻撃1 AP、武器切替1 AP。攻撃力は1で、攻撃後は元のマスに留まります。APを使い切ると敵ターンへ進みます。敵ターンは2段階・約0.46秒です。敵ユニットのHPも盤面上の赤いハートで表示します。

- **金／ハンマー**：前3方向・左右・後ろ。
- **銀／剣**：前3方向・後ろ斜め2方向。
- **桂／斧**：前2マス＋左右1マス。途中の駒と地雷を飛び越えます。

前方はプレイヤーの向いている方向です。初期状態は画面上向きで、移動範囲と攻撃範囲は同じです。

左上のHP・AP欄の「向き変更」または盤面のプレイヤーを押すと、右側で4方向と3×3の範囲を確認できます。方向の選び直しとキャンセルは無料で、「この向きにする 1 AP」を押したときだけ向きを変更します。同じ向きは確定できません。移動・攻撃・武器切替で向きは自動変更されません。魔弾精霊・隠密妖精の配置範囲と敵の攻撃範囲回避も、確定済みの向きを使います。

| 敵 | HP | AP | 行動 |
| --- | --- | --- | --- |
| 歩兵 | 1 | 2 | 縦横1マス。攻撃可能なら予告なしで攻撃。それ以外は接近→包囲→突撃予告 |
| 地雷兵 | 1 | 2 | 縦横1マス移動→移動先へ地雷設置。飛行で地雷無効 |
| 重装兵 | 2 | 1 | 縦横1マス。前進して前線を形成 |

歩兵には距離2の別々の包囲位置を割り当てます。接近・包囲中は現在の武器の攻撃範囲、地雷、味方の密集を避けるように移動候補を評価します。評価は目標までの距離×10、攻撃範囲+20、地雷+25、隣接する味方1体につき+5です。危険なマスも禁止ではなく、進路によっては通ります。

歩兵は予告の有無に関係なく、隣接していれば1 APで攻撃します。残り2 APで移動と攻撃ができる場合も、そのターンに接近して攻撃します。移動先の敵・障害物・地雷を考慮し、安全な前進候補があれば優先します。

敵ターン終了時に距離2以内の歩兵が2体以上いる、包囲が2ターン続く、または歩兵が残り1体の場合、近い歩兵に黄色い「！」が付きます。次の敵ターンに突撃する予告で、その間に移動・迎撃・武器切替ができます。突撃時は武器の攻撃範囲を避けず、味方が倒れても予告を取り消しません。攻撃は1 APで1ダメージ、隣接状態からは最大2回攻撃します。探索者が離れた場合は追跡し、届かなければ接近に戻ります。地雷兵は探索者から距離3付近を動きます。

地雷は着地した地上ユニットに1ダメージを与えて消滅。敵味方の区別はありません。地雷兵は踏まず、桂は着地マスだけで判定します。歩兵・重装兵は地雷を避ける評価を持ちますが、進路によって踏む場合があります。

## 精霊とバッグ

左下に消耗品ショートカット3枠とバッグを表示します。各精霊1個から開始し、次の戦闘へ残数を引き継ぎます。やり直し・全3戦終了後の再挑戦では各1個に戻ります。設置済みの妖精は次の戦闘には残りません。

バッグはスクロール可能な一覧です。カードをクリックすると使用対象を選べます。「登録」を押して左のショートカットを選ぶと、その枠に登録します。登録済みアイテム同士は入れ替わります。バッグの開閉・登録・対象選択・キャンセルは無料。発動時だけ1 APと1個を消費し、最後のAPを使うと敵ターンになります。効果説明はアイコンにカーソルを重ねて表示します。

| 精霊 | 使用方法・効果 |
| --- | --- |
| 魔弾精霊 | 現在の武器の攻撃範囲内にある空きマスを選び、縦横の向きを指定。即座にその方向の敵すべてへ1ダメージを与えて消滅。敵を貫通し、障害物・設置済み隠密妖精で止まる。斜め向き不可。 |
| 隠密妖精 | 現在の武器の攻撃範囲内にある空きマスに設置。残っている間は敵味方とも通行不可。縦横1マス以内に敵が入ると1体に1ダメージを与えて消滅。設置時に隣接している敵にも即時発動。複数の対象がいる場合はID順に1体を選ぶ。 |
| ワープ妖精 | 敵・障害物・隠密妖精がない盤面上の好きなマスへ瞬間移動。途中の駒・地雷は飛び越え、着地先の地雷は踏む。 |

魔弾は向き確定前に射線を表示します。右側の矢印、矢印キー、または配置マスと同じ行・列のマスをクリックして発射できます。方向指定前の配置は仮表示で、消費や盤面への影響はありません。

### アイテムの追加

`items/` の `.tres` が名前、説明、色、任意のアイコン画像、配置対象、方向指定の有無、AP、初期個数、効果スクリプトを持ちます。同じ効果の派生アイテムは定義を追加して `battle_model.gd` の `ITEMS` に登録すると、バッグに自動表示されます。独自効果は `scripts/items/` に `apply(model, cell, direction)` を実装して割り当てます。APと残数の消費・対象の検証は共通処理が担当します。

## 元プロジェクトとの関係

元データ：Godot上の名前が「Ruins Delver Prototype」のプロジェクト。本作は元プロジェクトを変更せず、独立した派生プロジェクトとして作成しています。

プレイヤーの3武器・4方向の新しい立ち姿シート、警察のスプライト、HP用メモリ部品、ガジェットアイコン、効果アトラス、フォントを元データからコピーしています。石床と壁は元の手続き描画の配色・陰影を引き継いでいます。地雷ドローン、重装兵の盾、地雷は同じ画面に合わせてコード描画を追加しています。

コード入力画面、ガジェットプログラムの実行処理、違法メモリ、ランダムダンジョン探索はこの版には組み込んでいません。HP5・武器切替1 AP・攻撃後移動なし・3戦構成は試作の設定で、難易度調整は今後のプレイ検証対象です。

## 構成

- `scripts/battle_model.gd`：盤面、HP/AP、武器、地雷、勝敗。
- `scripts/enemy_planner.gd`：包囲位置、状態遷移、2段階の敵行動。
- `scripts/infantry_behavior.gd`：歩兵の移動評価、行動候補、状態遷移の要求。
- `scripts/battle_view.gd`：ターン進行、入力、画面、アニメーション。
- `scripts/unit_view.gd`：元のスプライト、剣の方向別攻撃アニメーション、HP、重装兵・ドローンの描画。
- `scripts/animation/sword_motion.gd`：剣のコマ別再生時間、着弾タイミング、足元と大きさの補正。
- `scripts/weapon_effect.gd`：武器ごとの移動・攻撃エフェクト。
- `assets/sprites/effects/weapons/`：武器別の透過エフェクト画像。
- `assets/sprites/attacks/sword-attack-directions.png`：剣の方向別攻撃スプライトシート（上6・右5・下5・左5コマ）。左右は選択済みの振り上げ斬撃01・02・04・05・06。
- `scripts/movement/`：元プロジェクトの金・銀・桂と共通移動コード。
- `items/`・`scripts/items/`：消耗品の定義、個別効果、バッグ、アイコン。
- `assets/sprites/spirits/`：魔弾・隠密・ワープ精霊のピクセルアート。
- `tests/test_battle.gd`：ルールとターン進行の自動検証。
- `tests/test_facing.gd`：4方向の武器範囲、無料プレビュー、確定時のAP消費、向きの保持と入力の検証。
- `tests/test_items.gd`：精霊の効果、残数引継ぎ、入力、キャンセル、100回の消耗品込みランダム進行。

状態は `ENEMY / PLAYER / WON / LOST` で明示し、アニメーション中は入力をロックします。やり直しで古い非同期処理が混入しないよう世代番号を使っています。

## 武器エフェクト

移動は控えめな足元の演出、攻撃は短い閃光として再生します。ハンマーは土煙と衝撃波、アックスは跳躍・着地と振り下ろしです。剣はプレイヤーの現在の向きに合わせ、構え・斬撃・戻りに異なる時間を配分して約0.62～0.72秒再生します。剣は上向きの構えを0.2秒、右・下・左向きを0.25秒、斬撃の決めポーズを全方向0.2秒保持します。足元の基準点と頭部の幅で各コマを補正し、開始・終了時には通常の立ち絵を表示します。下向き立ち絵の拡大は維持しています。HPと突撃予告はエフェクトより手前に表示します。

剣の攻撃はルール上の処理を即時に確定し、敵のHP表示・ダメージ表示・点滅・消滅は上向き約0.265秒後、他の向きは約0.315～0.345秒後の着弾コマまで待ちます。生存した敵は短くのけぞります。入力再開・勝利画面・次の敵ターンは戻りの完了後です。

演出はAP・ダメージを変更しません。無効な操作では再生せず、やり直し時は残った演出を破棄します。アイテムと敵の既存エフェクトは維持しています。

## 検証

Godot 4.7.2でテストを実行できます。公開時点では、アイテム・武器エフェクト・騎兵・重装兵・剣アニメーションの各テストは成功しています。一方、`test_battle.gd` は211件、`test_facing.gd` は2件の既存チェックが失敗する状態です。これらの失敗は未解決です。難易度と評価値もプレイ調整の対象です。

武器エフェクトは `tests/test_weapon_effects.gd` で全3武器の移動・攻撃、剣の方向別アニメーション、AP、連打防止、演出の破棄、リセット中断を検証しています。

剣の表示は `tests/test_sword_animation.gd` で着弾とHP更新の同期、4方向、撃破・勝利、最終AP、途中リセットを検証します。続いて `python3 tools/check_sword_visuals.py` を実行すると、画像から足元と頭部を再計測し、実際の描画矩形による足元基準点の誤差1px以内・頭幅の誤差5%以内を確認します。計測は現在の銀髪・茶色ブーツ用です。画像や配色を変えた場合は `../animation-review/detected-landmarks.png` で検出位置も確認してください。これは足の関節や剣の軌道の自然さを保証するものではありません。

実画面の撮影は `godot --path . --script res://tests/capture_sword_animation.gd --fixed-fps 60 --disable-vsync -- after`（描画可能な環境が必要）、GIF作成は `python3 tools/build_sword_review.py` です。比較GIFには `../animation-review/before/` の変更前キャプチャも必要です。出力先は `../animation-review/` です。

向き変更は `tests/test_facing.gd` で4方向の範囲、精霊の配置範囲、方向の選び直し・取消、確定ボタン、最終APからの敵ターン、やり直しを検証します。公開時点ではこのテストの2チェックが失敗します。

精霊の検証では、効果・APと残数・障害物・地雷・勝敗・操作を確認しています。バッグ、通常盤面、魔弾の方向指定画面をGodotで描画して視覚確認しています。

```sh
godot --headless --path . --script res://tests/test_battle.gd

godot --headless --path . --script res://tests/test_items.gd

godot --headless --path . --script res://tests/test_weapon_effects.gd

godot --headless --path . --script res://tests/test_facing.gd
```
